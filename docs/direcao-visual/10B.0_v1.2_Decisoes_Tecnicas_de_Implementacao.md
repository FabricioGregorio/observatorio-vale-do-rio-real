# 10B.0 v1.2 — Decisões Técnicas de Implementação

**Projeto:** Observatório do Vale do Rio Real  
**Fase:** Tarefa 10B — Evolução visual e territorial da Home  
**Documento:** Direção Técnica de Implementação  
**Versão:** 1.2  
**Status:** Aprovado para orientar implementação  
**Data:** 2026-09-03

---

# 1. Objetivo deste documento

Este documento complementa o **10B.0 — Documento de Direção Visual** e define as decisões técnicas que devem orientar a implementação da próxima fase da Home.

O objetivo é evitar decisões improvisadas durante o desenvolvimento e garantir que a evolução visual preserve os princípios arquiteturais do projeto:

- transparência;
- preservação documental;
- valorização territorial;
- acessibilidade;
- baixo peso;
- independência de serviços externos;
- experiência editorial.

A Home não deve parecer um site institucional genérico.

Ela deve funcionar como:

> um arquivo público vivo do território.

---

# 2. Decisão principal: arquitetura do mapa

> **Substituído pela ADR-009** (`docs/decisoes/ADR-009-biblioteca-do-mapa-territorial.md`), que escolheu MapLibre GL JS no lugar de D3 + SVG.


## Escolha definida

O mapa territorial será desenvolvido utilizando:

- SVG;
- GeoJSON próprio;
- renderização controlada pelo projeto;
- componentes React isolados.

## Não utilizar inicialmente

Não utilizar:

- Google Maps;
- Mapbox;
- Leaflet.

## Motivo

O objetivo do mapa não é navegação geográfica.

O objetivo é:

- apresentar municípios;
- contar uma história territorial;
- destacar áreas pesquisadas;
- conectar território, memória e pesquisa.

Um mapa tradicional adicionaria elementos desnecessários:

- dependência externa;
- custos futuros;
- identidade visual genérica;
- aparência de aplicativo de localização.

A experiência desejada é mais próxima de:

- atlas digital;
- arquivo cultural;
- publicação interativa.

# 4. Estratégia Server Component / Client Component

Regra:

O mapa deve ser majoritariamente Server Component.

A interatividade deve existir somente onde for necessária.

## Server Component

Responsável por:

- carregar dados;
- preparar informações;
- entregar estrutura.

## Client Component

Permitido somente para:

- hover;
- clique;
- animações do mapa;
- controle de estado visual.

Objetivo:

```
Maioria Server Component

+

mínimo necessário de Client Component
```

# 5. Biblioteca escolhida

> **Substituído pela ADR-009** (`docs/decisoes/ADR-009-biblioteca-do-mapa-territorial.md`), que escolheu MapLibre GL JS no lugar de D3 + SVG.


## Escolha recomendada

### D3 + SVG

Motivos:

- controle visual completo;
- baixo peso;
- liberdade estética;
- integração natural com GeoJSON;
- possibilidade de criar uma identidade própria.

---

## Alternativas não escolhidas

### Mapbox

Não utilizar inicialmente.

Motivos:

- dependência externa;
- custo futuro;
- aparência de mapa comercial.

---

### Leaflet

Não utilizar inicialmente.

Motivos:

- foco em mapas operacionais;
- estética muito associada a aplicações tradicionais.

---

### React Simple Maps

Pode ser considerado no futuro caso reduza complexidade, mas a preferência inicial permanece D3 + SVG.

# 6. Organização dos dados territoriais

> **Superado em parte pela Consolidação 10B.2.1** (`10B.2.1_Consolidacao_Territorial_e_Camadas.md`), que define o recorte do Vale do Rio Real, o modelo de camadas e a lista de arquivos de dado.


Não utilizar um GeoJSON gigantesco contendo todo o Brasil.

Separar por finalidade:

```
sergipe.geojson

vale-rio-real.geojson

pontos-visita.json
```

Benefícios:

- menor carregamento;
- manutenção simples;
- maior controle editorial.

# 8. Pontos de visita de campo

Criar uma estrutura independente:

```
pontos-visita.json
```

Exemplo:

```json
[
 {
  "nome": "Recanto da Serra",
  "tipo": "natureza",
  "municipio": "Tobias Barreto",
  "foto": "",
  "coordenadas": []
 }
]
```

Essa estrutura permitirá futuramente:

- mapa de campo;
- linha do tempo;
- diário de pesquisa;
- acervo fotográfico.

---

# 9. Narrativa fotográfica

As fotografias reais devem ser prioridade.

Não utilizar imagens genéricas.

A narrativa recomendada:

## Caderno de Campo

Formato:

```
VISITA

Local

Fotografia

Data

Contexto

Equipe

Localização
```

O objetivo é aproximar o visitante da pesquisa.

# 10. Ilustrações dos participantes

A ideia será incorporada, mas seguindo uma regra:

Não criar mascotes.

A abordagem será:

## Retratos editoriais

Mistura de:

- ilustração documental;
- identidade cultural;
- elementos simbólicos.

Cada participante poderá possuir:

- nome;
- função;
- elemento visual associado;
- narrativa curta.

# 12. Logos institucionais e créditos PNAB

As marcas institucionais devem ser tratadas como bloco próprio.

Não misturar com identidade visual.

Criar futuramente:

```
CreditosInstitucionais.tsx
```

Responsável por:

- logos obrigatórias;
- créditos;
- apoiadores;
- financiadores.

A ordem e proporção devem seguir:

- edital específico;
- manual de aplicação de marcas;
- orientações oficiais.

Não criar composição definitiva sem manual.

---

# 13. Animações

A interação deve ser moderna, mas discreta.

Permitido:

- entrada suave de blocos;
- hover;
- transições;
- destaque territorial.

Evitar:

- excesso de movimento;
- efeitos decorativos;
- animações que prejudiquem leitura.

Prioridade:

```
informação > efeito visual
```

---

# 14. Paleta e identidade

Não alterar agora:

- cores;
- fontes;
- logos;
- tokens.

As fontes atuais permanecem como candidata:

- Archivo;
- Literata;
- IBM Plex Mono.

Motivo:

Elas comunicam:

- arquivo;
- pesquisa;
- documento;
- observação.

Qualquer mudança visual definitiva precisa de aprovação.

# 16. Decisões bloqueadas

Não implementar sem aprovação:

- nova paleta;
- troca de fontes;
- alteração de logo;
- nova identidade visual;
- mapa definitivo sem GeoJSON aprovado;
- créditos institucionais finais;
- ilustrações finais dos participantes.

---

# 17. Decisão final registrada

A implementação deve seguir:

✅ D3 + SVG + GeoJSON próprio  
✅ Sem dependência externa de mapas  
✅ Server Components como padrão  
✅ Client Component apenas para interação  
✅ Fotos reais como narrativa principal  
✅ Caderno de Campo como conceito editorial  
✅ Logos institucionais separadas da identidade  
✅ Preservação das fontes atuais  
✅ Evolução visual baseada em aprovação humana

Este documento serve como guia técnico oficial para a implementação da Tarefa 10B.
