**Projeto:** Observatório do Vale do Rio Real\
**Fase:** Tarefa 10B\
**Documento:** Especificação operacional de implementação\
**Versão:** 1.3\
**Status:** Documento de execução\
**Data:** 2026-09-03

------------------------------------------------------------------------

# 1. Objetivo

Este documento transforma as decisões visuais e técnicas anteriores em
uma especificação prática para implementação da Home.

A Home deve evoluir de uma estrutura institucional básica para uma
experiência digital que represente:

-   arquivo público vivo;
-   território;
-   pesquisa;
-   memória;
-   transparência;
-   preservação documental.

A implementação deve respeitar a arquitetura já existente e não deve
criar informações não aprovadas.

------------------------------------------------------------------------

# 2. Contexto atual

A Home possui atualmente a primeira fatia estrutural da Tarefa 10A:

Implementado:

-   AberturaObservatorio;
-   CaminhosPrioritarios;
-   CartaoCaminho;
-   ChamadaAcervo;
-   hierarquia semântica;
-   testes básicos;
-   acessibilidade.

Ainda bloqueado:

-   texto institucional final;
-   indicadores;
-   comparativo municipal;
-   conteúdo territorial;
-   MDX. 

A Tarefa 10B deve evoluir a apresentação visual e territorial sem
quebrar essas restrições.

------------------------------------------------------------------------

# 3. Princípios obrigatórios

A implementação deve seguir:

## Informação antes de decoração

Todo elemento visual deve possuir função:

-   informar;
-   orientar;
-   preservar;
-   conectar usuário ao acervo.

## Não inventar conteúdo

Não criar:

-   números;
-   resultados;
-   narrativas de impacto;
-   comparações;
-   depoimentos.

## Valorizar o território

O diferencial do projeto é:

-   pessoas;
-   lugares;
-   memória;
-   pesquisa de campo.

------------------------------------------------------------------------

Fluxo:

    Cabeçalho existente

    ↓

    ↓

    ↓

Não criar blocos vazios.

# 6. Abertura da Home

Objetivo:

Ser a ficha-mestra do Observatório.

Elementos:

-   nome oficial;
-   identificação pública;
-   descrição aprovada;
-   chamada principal para Prestação de Contas.

Prioridade visual:

1.  Prestação de Contas;
2.  Pesquisa;
3.  Acervo.

Não utilizar:

-   slogans inventados;
-   textos promocionais genéricos.

------------------------------------------------------------------------

# 7. Mapa territorial

> **Superado em parte pela Consolidação 10B.2.1** (`10B.2.1_Consolidacao_Territorial_e_Camadas.md`), que define o recorte do Vale do Rio Real, o modelo de camadas e a lista de arquivos de dado.


## Tecnologia

> **Substituído pela ADR-009** (`docs/decisoes/ADR-009-biblioteca-do-mapa-territorial.md`), que escolheu MapLibre GL JS no lugar de D3 + SVG.


Implementação:

-   D3;
-   SVG;
-   GeoJSON próprio.

Não utilizar:

-   Google Maps;
-   Mapbox;
-   Leaflet.

------------------------------------------------------------------------

## Estrutura de dados

    src/dados/territorio/

    sergipe.geojson

    vale-rio-real.geojson

    pontos-visita.json

------------------------------------------------------------------------

## Experiência

Estado inicial:

-   Sergipe completo;
-   destaque para Vale do Rio Real.

Interação:

Ao passar mouse:

-   município destacado;
-   ficha informativa exibida.

Ao clicar:

-   abrir informações territoriais futuras.

------------------------------------------------------------------------

# 8. Municípios

O mapa deve tratar municípios como objetos individuais.

Cada município deve possuir:

-   geometria própria;
-   identificação;
-   estado visual;
-   possibilidade futura de receber dados.

Não adicionar informações comparativas sem fonte oficial.

------------------------------------------------------------------------

# 9. Pontos de visita

Locais previstos:

-   Recanto da Serra;
-   Centro Cultural e Museu Borda da Mata;
-   Serra dos Macacos;
-   Ilha Grande.

A estrutura deve permitir:

-   marcador;
-   fotografia;
-   descrição futura;
-   localização.

------------------------------------------------------------------------

# 10. Caderno de Campo

A narrativa territorial deve priorizar fotografias reais.

Modelo:

    Local

    Imagem

    Data

    Contexto

    Registro de campo

Não utilizar imagens genéricas.

------------------------------------------------------------------------

# 11. Identidade visual

Não alterar sem aprovação:

-   cores;
-   fontes;
-   logos;
-   tokens.

Manter inicialmente:

-   Archivo;
-   Literata;
-   IBM Plex Mono.

------------------------------------------------------------------------

# 12. Elementos gráficos

Podem ser utilizados futuramente:

-   luneta da identidade;
-   elementos do Coletivo Tobias, sou Eu!;
-   ilustrações dos participantes.

Regra:

Não transformar participantes em mascotes.

Preferir:

-   retratos editoriais;
-   ilustração documental;
-   identidade cultural.

------------------------------------------------------------------------

# 13. Logos institucionais

Criar bloco separado:

    CreditosInstitucionais

Responsável por:

-   marcas obrigatórias;
-   parceiros;
-   financiamento.

Não misturar com identidade visual.

A aplicação final depende de:

-   edital;
-   manual de marcas;
-   aprovação.

------------------------------------------------------------------------

# 14. Responsividade

Obrigatório:

Mobile first.

O mapa deve funcionar em:

-   desktop;
-   tablet;
-   celular.

Em telas pequenas:

-   permitir interação por toque;
-   não depender apenas de hover.

------------------------------------------------------------------------

# 15. Acessibilidade

Obrigatório:

-   navegação por teclado;
-   foco visível;
-   contraste adequado;
-   textos alternativos;
-   sem informação exclusivamente visual.

O mapa deve possuir alternativa textual.

------------------------------------------------------------------------

# 16. Performance

Evitar:

-   imagens pesadas;
-   bibliotecas desnecessárias;
-   chamadas externas.

Priorizar:

-   arquivos otimizados;
-   carregamento progressivo;
-   componentes estáticos.

------------------------------------------------------------------------

# 17. Arquivos permitidos inicialmente

Esperado:

    src/app/page.tsx

    src/componentes/home/*

    src/dados/territorio/*

    testes/*

Não alterar:

    db/

    migrations/

    tokens.css

    layout global

    prestacao-de-contas

    anexos.json

sem autorização.

------------------------------------------------------------------------

# 18. Ordem de implementação

## Etapa 1
